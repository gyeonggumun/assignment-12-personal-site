# 과제 12 제출 확인 문서

결과물 URL: https://assignment-12-personal-site-gyeonggumuns-projects.vercel.app/

이 문서는 제출 직전에 사이트와 문서가 체크리스트에 맞는지 확인하기 위한 안내서입니다. ZIP 파일은 별도로 묶어 제출합니다.

## 무엇을 하나요 (3단계 이내)

1. 결과물 URL을 새 시크릿 창에서 열고 계정 생성·로그인·인증·CAPTCHA 없이 첫 화면이 보이는지 확인합니다. `이야기`에서 고난 장면, 회복 과정, 현재의 변화와 세 역량의 날짜 태그를 확인합니다.
2. `기록`과 `오늘까지의 기록 흐름`에서 공개 데이터의 기간·완료율·출처를 확인합니다. `새 기록`에서 검증된 13주 CSV 또는 동료 이름이 마스킹된 리추얼 JSON을 넣고 결과를 만든 뒤, 같은 입력을 두 번 실행해 결과가 같은지 비교합니다.
3. `대표작`의 논문 링크, 앱 예정 자리, `문서`의 세 PDF 다운로드를 확인하고 `device/README.md`에 따라 새 폴더에서 갱신 장치를 실행합니다.

## 무엇이 보이면 통과인가요

첫 화면에서 이름·한 줄 소개가 보이고, 이야기·기록·대표작·문서·새 기록이 모두 열리면 통과입니다.
수치는 원자료와 일치하고 출처가 표시되며, PDF 다운로드와 업데이터 재실행 결과가 같아야 합니다.

## 안될 때 확인할 부분

화면·수치·PDF 중 하나라도 다르면 `src/data.js`와 최신 Vercel 배포를 확인합니다.
`입력 대기`는 검증 CSV가 없는 상태이므로 임의의 숫자를 넣지 않습니다.

## AI와 나의 판단 3줄

- AI에게 맡긴 일: 문헌 구조화, 다국어 표현, 정적 웹 코드 초안과 후보 문장 계산.
- 내가 직접 판단한 일: 경험의 사실 여부, 날짜·역량 연결, 공개 범위와 지원 문장을 결정했습니다.
- 따르지 않은 제안: 실제 기록이 없는 수치를 만들거나 치료 효과를 주장하는 제안은 사용하지 않았습니다.

## 캡처해야 할 부분

1. 첫 화면: 이름·한 줄 소개·핵심 역량·공개 URL을 한 화면에 캡처합니다.
2. 이야기: 고난·회복 장면과 세 역량의 날짜 태그를 캡처합니다.
3. 기록: 기록 기간·완료율·출처가 보이는 영역을 캡처합니다.
4. 대표작: 논문 링크와 앱 `제작 예정` 표시를 캡처합니다.
5. 문서·새 기록: 세 PDF 링크와 결과 생성·동일 결과 확인을 캡처합니다.
6. 장치 실행: 실행 명령과 두 결과 파일 생성 화면을 캡처합니다.

## 제출 파일 구성

- 결과물 URL: 위 Vercel 주소 1개
- 문서: 이력서 PDF, 자기소개서 PDF, 경력기술서 PDF
- 장치 ZIP: `device/` 실행 소스, `README.md`, 마지막 결과 두 파일
